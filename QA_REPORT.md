# NORMATRIX VND Analytics v1.1.2 — итоговый QA

Дата проверки: 23.09.2026

## Итог

Ядро загрузки, локального анализа, машинных отчётов `.normatrix`, дедупликации и проверенной выгрузки прошло программные приёмочные тесты. Официальный Excel/PDF и «Приложение 3» теперь используют только замечания со статусом **«Подтверждено специалистом»**. Отклонённые замечания исключаются из официальной выгрузки и из рекомендаций структурным подразделениям, но решение «отклонено» сохраняется в `.normatrix` и восстанавливается при повторном импорте.

## Что проверено и прошло

### Корневые данные
- `vnd_master.xlsx` — 314 постоянных `VND_ID`, все 314 уникальны, диапазон `VND-000001`…`VND-000314`.
- `structure.xlsx` имеет ожидаемый лист `STRUCTURE` и корректные шапки.
- `vnd_master.xlsx`, `structure.xlsx`, `templates/appendix3_template.xlsx` — корректные XLSX/ZIP-контейнеры.
- Корневые файлы отдаются через локальный HTTP с HTTP 200.
- JSON-конфигурации валидны.

### Загрузка исходного ВНД
На демонстрационном `VND-000001_DEMO.zip` пройден полный путь:
- ZIP распакован;
- `VND-000001` сопоставлен с реестром;
- `MAIN.txt` определён как основной, `APP01.txt` как приложение;
- выделены структурные пункты;
- найдена отсылочная норма;
- найден потенциальный дискреционный фактор;
- различие сроков **5 и 3 рабочих дня** классифицировано как потенциальное противоречие, а не дубль;
- ссылка **«статья 64 АППК РК»** извлечена вместе с номером статьи и отнесена к НПА РК.

### Машинный отчёт `.normatrix`
Проверено:
- формирование отчёта одного ВНД;
- сохранение структурированных норм без оригинального PDF/DOC/DOCX/JPG;
- обратная загрузка `.normatrix`;
- повторное получение 6 структурированных норм тестового ВНД без повторного OCR;
- импорт ZIP-пакета из нескольких `.normatrix`;
- проверка версии схемы;
- предупреждение при другой версии правил анализа;
- удаление нечитаемого бинарного хвоста из импортированных текстов;
- временный VND_ID не допускается к экспорту `.normatrix`.

### Дедупликация
Проверено:
- два одинаковых представления одного `VND_ID` не суммируются дважды;
- при одновременной загрузке исходного ВНД и `.normatrix` приоритет получает исходный ВНД;
- два `.normatrix` одного `VND_ID` с разными сигнатурами дают критическое предупреждение «Конфликт отчётов ВНД» и не суммируются;
- лимит междокументных сравнений теперь считается по **уникальным парам**, а не повторным совпадениям токенов.

### Решения специалиста и достоверность отчёта
Отдельный тест: 4 замечания со статусами:
- 1 `confirmed`;
- 1 `rejected`;
- 1 `ai`;
- 1 `legal`.

Результат:
- лист Excel **«Подтверждено»**: 1 строка;
- лист **«На рассмотрении»**: 2 строки (`ai` + `legal`);
- **«Приложение 3»**: 1 строка — только подтверждённая;
- **«Рекомендации СП»**: сформированы только по подтверждённому замечанию;
- отклонённое замечание **не присутствует** в деталях человекочитаемой выгрузки;
- в сводке отображается только число отклонённых с пояснением «не включено»;
- `.normatrix` сохраняет статус `rejected`, чтобы после повторной загрузки портал не предлагал такое замечание заново;
- поля «Предпринимаемые меры» и «Сведения об актуализации» сохраняются в `.normatrix` и восстанавливаются после импорта.

### Приложение 3
Шаблон и runtime-выгрузка имеют 8 колонок:
1. № п/п;
2. Виды недостатков норм поведения;
3. Наименование ВНД;
4. Номер и дата принятия ВНД;
5. Структурные элементы документа;
6. Номер и наименование акта, которому не соответствует норма;
7. Предпринимаемые меры;
8. Сведения об актуализации.

Поддерживаются 8 видов недостатков:
1. Неэффективно реализуемые нормы;
2. Противоречащие нормы;
3. Устаревшие нормы;
4. Коррупциогенные нормы;
5. Дублирующие нормы;
6. Пробелы норм права;
7. Наличие излишних бланкетных и отсылочных норм;
8. Иное.

Категория присваивается автоматически как **предварительная классификация**. В официальный отчёт она попадает только после подтверждения специалистом.

### Безопасность сессии
- в коде нет записи пользовательских ВНД/результатов в `localStorage`, `sessionStorage`, `IndexedDB` или cookies;
- очистка сессии сбрасывает исходные ВНД, `.normatrix`, результаты и решения текущей вкладки;
- внешний Legal Verification получает только НПА РК и только при настроенном endpoint;
- внутренние акты ВЖДО и корпоративные акты КТЖ не отправляются во внешний модуль.

## Что нельзя считать подтверждённым на 100% в этой тестовой среде

### 1. Структурные подразделения — требуется ваш фактический `structure.xlsx`
Текущий файл в поставке содержит стартовые значения **«Блок ответственности: Ф.И.О.»**. Код распределения работает, но достоверность реальных подразделений будет только после замены содержания `structure.xlsx` на действующую оргструктуру с сохранением шапок.

### 2. CDN-библиотеки
Браузерные библиотеки SheetJS, JSZip, Mammoth, PDF.js и Tesseract.js сейчас подключаются через `cdn.jsdelivr.net`. В изолированной QA-среде внешний CDN недоступен, поэтому полный браузерный E2E для реального PDF/DOCX/XLSX/OCR здесь не был завершён. Код содержит проверку зависимостей и не должен молча продолжать работу при отсутствии библиотек.

Для production без зависимости от корпоративного Интернета рекомендуется разместить эти библиотеки локально в `vendor/`.

### 3. OCR
Логика очереди OCR и повторной сборки анализа проверена программно. Реальное качество OCR зависит от качества скана и доступности языковых данных Tesseract. Низкая уверенность OCR помечается предупреждением и требует сверки оригинала.

### 4. Старый DOC
Старый бинарный `.doc` обрабатывается локальным best-effort извлечением. Текст с низкой смысловой надёжностью автоматически исключается из поиска дублей/противоречий. Для юридически значимых выводов старый DOC необходимо сверять с оригиналом.

### 5. RAR
RAR текущей браузерной сборкой **не поддерживается**. Поддерживаемый контейнер одного ВНД — ZIP.

### 6. Онлайн-проверка законодательства
`legalVerification.endpoint` не настроен. НПА извлекаются и классифицируются, но портал не выдаёт ложный статус «актуально». Реальная проверка актуальности требует отдельного защищённого endpoint.

### 7. Глубокий ИИ/LLM
Статическая версия использует локальные правила, текстовую близость и эвристики. Категории `PM06` (пробелы) и сложные смысловые конфликты требуют особенно осторожной экспертной проверки; полноценный LLM-анализ полного текста не подключён, чтобы ВНД автоматически не уходили во внешний сервис.

## Правило использования результата

- **Экран правового мониторинга** = рабочая зона, где видны кандидаты, подтверждённые и отклонённые замечания.
- **Проверенный Excel/PDF** = только подтверждённые замечания; кандидаты вынесены отдельно в Excel «На рассмотрении».
- **Приложение 3** = только подтверждённые замечания.
- **Рекомендации СП в выгрузке** = только по подтверждённым замечаниям.
- **`.normatrix`** = машинная память анализа: сохраняет также `rejected`/`legal`, чтобы решения специалиста не терялись между сессиями.
